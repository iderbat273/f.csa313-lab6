## 3. Хэсэг A — Category-Partition

### A1. Сонголт ба төлөөлөх утгууд

| Параметр | Сонголт / төлөөлөх утга | Тайлбар |
|---|---|---|
| From | Valid | Эх данс байгаа, царцаагдаагүй |
| From | Frozen | Эх данс байгаа боловч царцаасан |
| From | Missing | Эх данс байхгүй |
| To | Valid | Хүлээн авагч данс байгаа, From-оос өөр |
| To | Missing | Хүлээн авагч данс байхгүй |
| To | SameAsFrom | Хүлээн авагчийн ID эх дансны ID-тай ижил |
| Amount | Normal | Эерэг, үлдэгдэл ба өдрийн лимитэд багтсан |
| Amount | Zero | 0 буюу тэгтэй тэнцүү; хүчингүй |
| Amount | OverBalance | Хөрвүүлсний дараах дүн үлдэгдлээс их |
| Amount | OverLimit | Хөрвүүлсний дараах дүн өдрийн лимитээс их |
| Currency | Same | Гүйлгээний валют дансны валюттай ижил |
| Currency | Different | Валют өөр тул ханшийн хөрвүүлэлт хийнэ |

Далд орчны хүчин зүйлс:

- Эх дансны үлдэгдэл болон валют.
- Өдрийн лимит болон тухайн өдөр өмнө нь ашигласан лимит.
- Хүлээн авагч дансны оршин байгаа эсэх, валют.
- Валютын ханш болон хөрвүүлэлтийн нарийвчлал.

Эдгээр орчны хүчин зүйлс нь бодит `amount`-ийн утга ямар үр дүн өгөхийг тодорхойлно. Иймээс `Normal`, `OverBalance`, `OverLimit` нь зөвхөн тоон хэмжээ бус, дансны төлөв ба хөрвүүлэлтийн дараах нөхцөлөөр тодорхойлогдоно.

### A2. Хязгаарлалт ба тэмдэглэгээ

| Сонголт / утга | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| From=Valid | [SINGLE] | Амжилттай шилжүүлгийн суурь кейст эх данс хүчинтэй байх ёстой. |
| From=Frozen | [ERROR] | Царцаасан эх данс шилжүүлэг хийх эрхгүй. |
| From=Missing | [ERROR] | Эх данс байхгүй тул `ERROR_NO_FROM` буцаана. |
| To=Valid | [SINGLE] | Амжилттай шилжүүлгийн суурь кейст хүлээн авагч хүчинтэй. |
| To=Missing | [ERROR] | Хүлээн авагч олдохгүй тул `ERROR_NO_TO` буцаана. |
| To=SameAsFrom | [ERROR] | Эх ба хүлээн авагч данс ижил тул `ERROR_SAME_ACCOUNT` буцаана. |
| Amount=Normal | [SINGLE] | Амжилттай шилжүүлгийн суурь утга. |
| Amount=Zero | [ERROR] | `amount <= 0` тул `ERROR_BAD_AMOUNT` буцаана. |
| Amount=OverBalance | [ERROR] | Хөрвүүлсний дараах дүн үлдэгдлээс их тул `ERROR_INSUFFICIENT` буцаана. |
| Amount=OverLimit | [ERROR] | Хөрвүүлсний дараах дүн өдрийн лимитээс их тул `ERROR_LIMIT` буцаана. |
| Currency=Same | [SINGLE] | Валют хөрвүүлэхгүй замыг шалгана. |
| Currency=Different | [IF/property] | Валют өөр үед ханшийн хөрвүүлэлт хийж, дараах дүнгээр үлдэгдэл ба лимитийг шалгана. |
| From=Missing ⇒ Amount=Normal | [IF] | Эх данс байхгүй үеийн үндсэн алдааг тусгаарлахын тулд amount-ийн бусад алдааг хориглоно. |
| To=Missing ⇒ Amount=Normal | [IF] | Хүлээн авагч байхгүй үеийн үндсэн алдааг тусгаарлахын тулд amount-ийн бусад алдааг хориглоно. |

`[ERROR]` нь алдааны төлөөлөх утга, `[SINGLE]` нь суурь буюу тусгаарлан шалгах утга, `[IF]` нь нөхцөлт хязгаарлалт, `[IF/property]` нь бусад сонголт болон орчны шинжээс хамаарах зан төлөвийг тэмдэглэнэ.

#### Бүрэн олонлог ба хязгаарлалтын тооцоо

Энэ тооцоонд A1 хүснэгтийн 4 параметрийн сонголтуудыг ашиглав:

- From: 3 утга
- To: 3 утга
- Amount: 4 утга
- Currency: 2 утга

Хязгаарлалтгүй бүрэн олонлог:

`N = 3 × 3 × 4 × 2 = 72`

`From=Missing` үед `Amount` нь `Normal` байх ёстой. Зөрчих комбинацын тоо:

`1 × 3 × 3 × 2 = 18`

`To=Missing` үед `Amount` нь `Normal` байх ёстой. Зөрчих комбинацын тоо:

`3 × 1 × 3 × 2 = 18`

Хоёр хязгаарлалтыг зэрэг зөрчсөн комбинацууд дээрх хоёр тоонд давхар орсон тул нэг удаа буцаан нэмнэ:

`1 × 1 × 3 × 2 = 6`

Иймээс хязгаарлалтын дараах олонлог:

`M = 72 − 18 − 18 + 6 = 42`

**Үр дүн: `72 → 42`.** Энэ нь category-partition-ийн хязгаарлалттай бүрэн олонлог. PICT-ийн 12 мөр бол бүх 42 комбинацыг жагсаасан хэрэг биш, харин pairwise хамралт үүсгэсэн багц юм.

#### Давуу эрэмбэ

Олон алдаа зэрэг тохиолдвол энэ лабораторид дараах тестийн oracle-ийг сонгов:

1. `ERROR_NO_FROM`
2. `ERROR_FROZEN`
3. `ERROR_NO_TO`
4. `ERROR_SAME_ACCOUNT`
5. `ERROR_BAD_AMOUNT`
6. `ERROR_INSUFFICIENT`
7. `ERROR_LIMIT`

Энэ эрэмбэ нь серверийн баталгаажсан бодит хэрэгжүүлэлт биш, лабораторийн тест дизайн хийхэд зориулж сонгосон таамаглал юм. Бодит код байхгүй учраас олон алдааны буцах дарааллыг туршилтаар тогтоогоогүй.

### A3. Спецификацийн хүснэгт

`currency` нь дансны валюттай ижил эсвэл өөр байж болно. `Normal` нь хөрвүүлсний дараах дүн үлдэгдэл болон өдрийн лимитэд багтсан гэж үзнэ.

| № | From | To | Amount | Currency | Хүлээгдэх үр дүн |
|---:|---|---|---|---|---|
| 1 | Valid | Valid | Normal | Same | 201 `{"result":"OK"}` |
| 2 | Valid | Valid | Normal | Different | 201 `{"result":"OK"}` |
| 3 | Missing | Valid | Normal | Same | 200 `ERROR_NO_FROM` |
| 4 | Frozen | Valid | Normal | Same | 200 `ERROR_FROZEN` |
| 5 | Valid | Missing | Normal | Same | 200 `ERROR_NO_TO` |
| 6 | Valid | SameAsFrom | Normal | Same | 200 `ERROR_SAME_ACCOUNT` |
| 7 | Valid | Valid | Zero | Same | 200 `ERROR_BAD_AMOUNT` |
| 8 | Valid | Valid | OverBalance | Same | 200 `ERROR_INSUFFICIENT` |
| 9 | Valid | Valid | OverLimit | Same | 200 `ERROR_LIMIT` |
| 10 | Missing | Valid | Zero | Same | 200 `ERROR_NO_FROM` — давуу эрэмбээр |
| 11 | Frozen | Missing | Normal | Different | 200 `ERROR_FROZEN` — давуу эрэмбээр |
| 12 | Valid | Missing | OverLimit | Same | 200 `ERROR_NO_TO` — давуу эрэмбээр |

Эдгээр нь 12 спецификаци бөгөөд амжилттай шилжүүлэг, алдааны долоон анги, хоёр валютын нөхцөл, SINGLE суурь зам болон олон алдаа зэрэг тохиолдох нөхцөлийг хамруулна. Давхар алдааны мөрүүдийн oracle нь дээр сонгосон эрэмбэд тулгуурласан.

## 4. Хэсэг B — PICT

### B1. Browser model

`browser.model` файлд дараах сонголтууд орсон:

- Content: Allow, Restrict, Block
- Cookies: Allow, Restrict, Block
- Popups: Yes, No
- Addons: Yes, No
- Attacks: Yes, No
- Forgeries: Yes, No

Бүрэн олонлог:

`3 × 3 × 2 × 2 × 2 × 2 = 144`

`results/browser-2way.txt` болон `results/browser-3way.txt` файлуудын толгой мөрийг хассан тоо:

| Хамралт | PICT мөрийн тоо |
|---|---:|
| 2-way | 10 |
| 3-way | 20 |
| Бүрэн олонлог | 144 |

Лекцийн гараар хийсэн 9 мөртэй жишээнээс PICT-ийн 2-way үр дүн 1 мөрөөр олон. PICT greedy алгоритмаар тухайн алхамд хамрагдаагүй хослолуудыг нөхөж мөр сонгодог тул заавал хамгийн цөөн мөрийн шийдэл олно гэсэн баталгаа байхгүй. 3-way гаралт 20 мөр бөгөөд 144 бүрэн комбинацыг бүгдийг туршсан гэсэн үг биш; гурван параметрийн утгуудын бүх хослолыг хамруулах зорилготой.

### B2. Transfer model-ууд

| Model | Тайлбар | PICT мөрийн тоо |
|---|---|---:|
| `transfer-nc.model` | Хязгаарлалтгүй | 13 |
| `transfer.model` | IF хязгаарлалттай, seed ашигласан | 12 |
| `transfer-neg.model` | Алдааны утгыг `~`-ээр тэмдэглэсэн | 16 |

Happy path-ийн шалгуур: `From=Valid`, `To=Valid`, `Amount=Normal`. Валют `Same` эсвэл `Different` байж болно.

| Model | Happy path мөрийн тоо | Нэг мөр дэх negative утгын тоо |
|---|---:|---|
| `transfer-nc.model` | 1 | Бүгд 0 |
| `transfer.model` | 1 | Бүгд 0 |
| `transfer-neg.model` | 2 | Алдааны мөр бүрт хамгийн ихдээ 1 |

`transfer.model`-д `transfer.seed` файлын `Valid / Valid / Normal / Same` мөрийг `/e:transfer.seed` ашиглан оруулсан. Энэ seed нь happy path-ийг заавал гаралтад байлгахын тулд хэрэглэгдсэн.

Negative утгын `~` тэмдэглэгээ нь нэг мөрөнд олон алдааг зэрэг оруулах эрсдэлийг багасгаж, нэг алдааг тусгаарлан шалгах боломж өгдөг. Ийм үед Missing данс болон amount-ийн алдаа нэг мөрөнд зэрэг орохгүй тул A2-ын `IF` хязгаарлалт pairwise model-ийн хувьд давхар алдааг арилгах шаардлага багатай болдог. Гэхдээ `~` нь дансны утга, бодит системийн төлөвийг өөрөө тодорхойлохгүй; семантикийн тайлбар болон A хэсгийн нөхцөлүүд хэрэгтэй хэвээр.

#### PICT гаралтаас бодит тест кейсүүд

Доорх кейсүүд нь PICT-ийн загварын утгыг бодит тестийн нөхцөл болгон тайлбарласан. Энэ лабораторид шилжүүлгийн сервер байхгүй учраас эдгээр oracle нь хэрэгжүүлэлт дээр ажиллуулж баталгаажуулсан үр дүн биш, тодорхойлолтоос гаргасан хүлээлт юм.

**TC-01 — Happy path**

- Setup: From данс `F100` байна, царцаагаагүй, үлдэгдэл 1000; To данс `T200` байна; өдөр ашигласан лимит нь үлдсэн лимитээс хэтрээгүй.
- Оролт:

```json
{
  "from": "F100",
  "to": "T200",
  "amount": 100,
  "currency": "MNT"
}
```

- Oracle: HTTP 201, `{"result":"OK"}`.

**TC-02 — Negative утгатай ганц алдаа**

- Setup: From данс `F100` хүчинтэй; To данс `T200` хүчинтэй; үлдэгдэл хангалттай; лимит хүрэлцээтэй.
- PICT загварын мөр: `Valid / Valid / ~Zero / Same`.
- Оролт:

```json
{
  "from": "F100",
  "to": "T200",
  "amount": 0,
  "currency": "MNT"
}
```

- Oracle: HTTP 200, `ERROR_BAD_AMOUNT`.

**TC-03 — Давхар алдаа, эрэмбийг шалгах**

- Setup: From данс байхгүй; To данс хүчинтэй; amount нь 0.
- A3 category-partition-ийн давхар алдааны нөхцөл (PICT-ийн гаралтын мөр биш): `Missing / Valid / Zero / Same`.
- Оролт:

```json
{
  "from": "NO-SUCH-ACCOUNT",
  "to": "T200",
  "amount": 0,
  "currency": "MNT"
}
```

- Oracle: HTTP 200, `ERROR_NO_FROM`, учир нь лабораторийн давуу эрэмбээр эх дансны шалгалт amount-ийн шалгалтаас өмнө байна.

### B3. Category-Partition ба PICT-ийн харьцуулалт

Category-partition нь утга бүрийн утга санаа, алдааны төрөл, давхар алдааны эрэмбийг тайлбарлахад илүү тохиромжтой. A3 хүснэгтээр тест бүрийн хүлээгдэх статус ба үр дүнг шууд уншиж болно. PICT нь параметрийн хослолуудын хамралтыг системтэй үүсгэж, гараар жагсаах ажлыг багасгадаг. Гэхдээ PICT-ийн pairwise хамралт нь бизнес дүрмийн бүрэн зөв байдлыг эсвэл олон алдааны oracle-ийг автоматаар батлахгүй. Хязгаарлалтгүй загварт хэд хэдэн алдаа нэг мөрөнд орж, аль алдаа буцах нь тодорхойгүй болж болно. Negative утгын тэмдэглэгээ энэ асуудлыг багасгадаг боловч бизнесийн нөхцөл, дансны төлөв, валют хөрвүүлэлтийн утгыг тайлбарлах шаардлага хэвээр. Хамгийн их бодол шаардсан алхам нь давхар алдааны давуу эрэмбэ болон үлдэгдэл/өдрийн лимитийг хөрвүүлэлтийн дараах дүнгээр шалгах дүрмийг зөв загварчлах байсан. Иймээс хоёр аргыг хамтад нь хэрэглэх нь илүү үр дүнтэй.

## 6. Хязгаарлалт ба баталгаажуулалт

Энэ лабораторид банкны шилжүүлгийн серверийн код өгөөгүй. Иймээс HTTP oracle-уудыг ажиллуулж шалгаагүй бөгөөд олон алдааны эрэмбэ нь тест дизайн хийхэд сонгосон таамаглал юм. PICT-ийн гаралтын мөрийн тоо нь загварын хамралтын хэмжээ болохоос системийн бодит алдааг илрүүлсэн нотолгоо биш.
